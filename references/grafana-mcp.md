# Работа через Grafana MCP или HTTP API

## Приоритет действий

1. Найти доступные инструменты Grafana и определить их возможности.
2. Прочитать datasource, папки, существующие дашборды и нужный dashboard JSON.
3. Выполнить тестовые запросы к datasource без изменения состояния.
4. Подготовить план панелей и показать существенные допущения.
5. Создать или изменить дашборд только после явного запроса пользователя на изменение.
6. Перечитать сохранённый дашборд и прогнать локальный валидатор для экспортированного JSON.

Имена MCP-инструментов не фиксировать в skill: разные версии сервера публикуют разные наборы tools. Искать возможности по смыслу: `dashboard`, `datasource`, `query`, `folder`, `annotation`, `alert`, `prometheus`, `loki`.

## Безопасность

- Не выводить service account token и заголовки авторизации.
- По умолчанию выполнять чтение и локальную подготовку JSON.
- Не перезаписывать существующий дашборд, если пользователь просил только ревью или проектирование.
- Перед записью сохранять UID и folder UID существующего дашборда.
- Не создавать дубликаты при повторном запуске: обновлять по UID или детерминированному идентификатору.
- Не менять datasource UID на имя datasource.

## Работа без MCP

Если MCP недоступен:

- принять экспорт dashboard JSON и сведения о datasource;
- подготовить JSON для импорта или provisioning;
- при разрешённом HTTP API использовать service account token из окружения, не записывая его в файлы;
- проверить результат после импорта чтением по UID.

## Отчёт о результате

Указать:

- создан или изменён ли реальный дашборд;
- UID и папку, если запись выполнялась;
- какие источники и запросы реально проверены;
- какие панели основаны на предположениях;
- результат `validate_dashboard.py`;
- оставшиеся UX-риски и риски стоимости запросов.
